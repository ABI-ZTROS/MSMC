# 复刻 WPF 原生 UI + 接入真实数据 计划

## 一、现状调研结论

### 当前问题
1. **底部冲突**：WPF 外层有一个状态栏（状态消息 + Web UI Mode + 时间），网页内容和这个状态栏重叠/冲突
2. **UI 变动太大**：现在的前端（Dashboard 风格）和原版 WPF 布局差异大，用户不习惯
3. **数据全是假的**：仪表盘、图表、服务器列表全是硬编码的 mock 数据
4. **硬编码多**：颜色、布局、配置很多写死在前端代码里

### 原版 WPF UI 结构（需复刻）

**主窗口布局**：
- 左侧：可折叠导航栏（服务器管理 / 配置编辑 / 系统监控 / 网络监控 / 设置）
- 顶部：操作条（每个页面不一样）
- 中间：主内容区
- 底部：WPF 状态栏（状态消息 + 时间）

**各页面结构**：

| 页面 | 核心布局 |
|------|----------|
| 服务器管理 | 左侧服务器列表（紧凑卡片）+ 右侧 Tab 切换（控制台/属性/JVM参数/...）+ 顶部操作条 |
| 配置编辑 | 左侧文件列表（280px）+ 右侧编辑区（动态表单） |
| 系统监控 | 顶部控制按钮 + 4个圆环仪表盘（CPU/内存/磁盘/线程）+ 折线图表 + 详细数据 |
| 网络监控 | 顶部统计卡片 + 网速仪表盘 + Tab 切换（端口占用/常见端口/端口桥接） |
| 设置 | 分组设置项卡片 |

### 桥接现状
- 已实现：C# ↔ JS 双向通信桥接、请求/响应/事件模型、主题同步
- 已注册 API：`ping`、`app:getTime`、`app:getInfo`、`app:getReadyState`
- 待接入：真实业务数据 API

## 二、整体方案

### 核心原则
1. **先复刻，后美化**：布局、功能、交互先 1:1 对齐 WPF 原版
2. **数据全走桥接**：所有真实数据通过桥接从 C# 后端获取，前端不硬编码业务数据
3. **解决底部冲突**：去掉 WPF 的状态栏，状态栏改到网页里，或者网页内容适配 WPF 状态栏的高度

### 分步实施

#### 阶段 1：布局复刻 + 底部冲突解决
- 修复底部状态栏冲突（去掉 WPF 状态栏，改到网页里）
- 复刻左侧导航栏（支持展开/折叠）
- 复刻整体布局框架

#### 阶段 2：页面复刻 + 真实数据接入
按优先级逐个页面复刻并接入真实数据：
1. **系统监控页**（最直观，仪表盘 + 图表，数据最好接）
2. **服务器管理页**（核心功能，服务器列表 + 操作）
3. **网络监控页**（端口占用 + 端口桥接）
4. **配置编辑页**（文件列表 + 动态表单）
5. **设置页**

#### 阶段 3：去硬编码 + 优化
- 主题/颜色全部从 C# 端同步
- 移除前端 mock 数据
- 细节优化和动效

## 三、详细步骤

### 阶段 1：布局框架 + 底部冲突

**修改文件**：
- `src/McServerGuard/Views/MainWindow.xaml` — 去掉底部状态栏
- `src/frontend/src/components/AppLayout.tsx` — 复刻 WPF 左侧导航 + 整体布局
- `src/frontend/src/components/Sidebar.tsx` — 左侧导航栏（可折叠）
- `src/frontend/src/App.tsx` — 调整路由和页面

**具体工作**：
1. 移除 WPF MainWindow 的底部状态栏（PrimaryDark 那一行），WebView2 占满窗口
2. 前端 AppLayout 复刻原版 WPF 的布局：左侧导航栏 + 右侧内容区
3. 导航栏实现 hover 展开/折叠（和 WPF 版行为一致）
4. 底部状态栏改到网页里，和原版 WPF 样式一致
5. 导航项：服务器管理 / 配置编辑 / 系统监控 / 网络监控 / 设置

### 阶段 2：页面复刻 + 接真实数据

#### 2.1 系统监控页（优先）

**C# 端新增 API**：
- `systemMonitor:getMetrics` — 获取当前系统指标（CPU/内存/磁盘/线程）
- `systemMonitor:getHistory` — 获取历史数据（用于图表）
- `systemMonitor:start` / `systemMonitor:stop` — 控制监控启停

**前端**：
- 复刻 4 个圆环仪表盘 + 控制按钮 + 图表区布局
- 接入真实数据，定时刷新
- 图表用真实历史数据绘制

#### 2.2 服务器管理页

**C# 端新增 API**：
- `server:list` — 获取服务器列表
- `server:start` / `server:stop` / `server:restart` — 服务器控制
- `server:console` — 控制台输出（事件推送）
- `server:properties` — 服务器属性
- `server:jvmParams` — JVM 参数

**前端**：
- 复刻左侧紧凑服务器列表 + 右侧 Tab 切换布局
- 接入真实服务器列表和状态
- 控制台输出实时更新

#### 2.3 网络监控页

**C# 端新增 API**：
- `network:getPorts` — 获取端口占用列表
- `network:getCommonPorts` — 常见端口列表
- `network:addPortForward` / `network:removePortForward` — 端口桥接管理
- `network:getPortForwards` — 当前端口转发列表

**前端**：
- 复刻顶部统计卡片 + 网速仪表盘 + Tab 切换布局
- 接入真实端口数据
- 端口桥接功能接入

#### 2.4 配置编辑页

**C# 端新增 API**：
- `config:listFiles` — 配置文件列表
- `config:getFile` — 获取文件内容
- `config:saveFile` — 保存文件
- `config:validate` — 验证配置

**前端**：
- 复刻左侧 280px 文件列表 + 右侧编辑区布局
- 动态表单生成（根据配置项类型）

#### 2.5 设置页

**C# 端新增 API**：
- `settings:get` — 获取所有设置
- `settings:update` — 更新设置
- `theme:get` / `theme:update` — 主题设置

**前端**：
- 复刻分组设置卡片布局
- 接入真实设置项

### 阶段 3：去硬编码 + 优化

**工作内容**：
1. 主题色、配色方案全部从 C# 端同步（通过 CSS 变量）
2. 移除所有 mock 数据和硬编码配置
3. 细节动效和交互优化
4. 性能优化（数据防抖、虚拟列表等）

## 四、依赖和注意事项

### 依赖
- 前端图表库：用现有方案（或引入 Recharts 等成熟库）
- 状态管理：zustand（已在用）
- 图标：需要找和 WPF 版 FontAwesome 对应的图标库

### 风险点
1. **数据量**：系统监控历史数据量大，需要考虑传输效率（节流/分页）
2. **实时性**：控制台输出、系统指标需要实时推送，用桥接事件
3. **兼容性**：确保所有 WPF 版本有的功能，网页版都有

### 底部冲突处理方案
采用方案：**去掉 WPF 状态栏，状态栏改到网页里**
- 好处：网页完全控制布局，不会有重叠/冲突
- 保持和原版一致的视觉效果（PrimaryDark 风格）
- 状态消息、时间等数据通过桥接实时更新

## 五、需要确认的问题

1. 底部状态栏：确认去掉 WPF 的状态栏，改到网页里，对吗？
2. 复刻精度：布局 1:1 对齐就行，还是连颜色、字体、间距都要和 WPF 版完全一致？
3. 页面顺序：先做系统监控页（数据好接，效果直观），然后服务器管理、网络、配置、设置，这个顺序 OK 吗？
4. 图表：WPF 版用的是 LiveCharts，网页版用什么图表库？（推荐 Recharts 或 ECharts）
